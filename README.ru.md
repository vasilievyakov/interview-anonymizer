# Interview anonymizer

[English version](README.md)

Открытый инструмент [лаборатории AI-агентов](https://ai-lab-agents.com). Мы сделали его для своих исследований и разобрали как кейс: как первая версия встретилась с живыми интервью и что пришлось поменять, описано в разделе «Как он сделан».

`anon` скрывает персональные данные в расшифровках интервью и таблицах перед отправкой в облачную LLM, а потом возвращает настоящие значения в ответ модели. Все, что касается исходных данных, выполняется на вашем компьютере и без сети.

```
ваш компьютер                                                           облако

 interview.md ─┐
 staff.xlsx  ──┤
               ▼
 anon keep ─> anon scan ─> anon review --web ─> anon apply ─> *.anon.* ──> любая LLM
 бренды,      правила,     локальная страница:  метки                │        │
 которые      Natasha,     скрыть, оставить,    + контроль утечек    │        │
 остаются     spaCy        добавить пропущенное       │              │        │
                                                      └─> .anon/vault.bin     │
                                                          (зашифрован)        │
 answer.restored.md <──────────── anon restore <──────────── answer.md <──────┘
```

Русский и английский. Таблицы: `.xlsx`, `.csv`. Тексты: `.md`, `.txt`, `.docx`.

![Полный цикл в терминале на выдуманных интервью: keep, scan, apply, restore](docs/media/demo.gif)

## Что видит модель

| Было | Уходит в модель |
|---|---|
| I'm John Carter from Brightline Logistics in Leeds, call me on 07700 900123. | I'm [PERSON_1] from [ORG_1] in [LOCATION_1], call me on [PHONE_1]. |
| Я Мария Ковалева из ООО «Северный ветер» в Казани, +7 912 345-67-89. | Я [ИМЯ_1] из [ОРГ_1] в [МЕСТО_1], [ТЕЛЕФОН_1]. |

В таблицах колонки с ФИО, почтой, телефоном, табельным номером и похожие заменяются по ячейкам. Числа, даты и формулы остаются как есть, так что модель по-прежнему может посчитать бюджет. Имена внутри текстовых ячеек (комментарии, заметки) тоже находятся.

Один человек получает одну метку во всех файлах проекта и в любой грамматической форме: «Марией Ковалевой», «Ковалева» и «Мария Ковалева» превращаются в `[ИМЯ_1]`.

## Установка

Нужен [uv](https://docs.astral.sh/uv/). Если его нет:

```sh
# macOS, Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows, PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Затем:

```sh
uv tool install https://github.com/vasilievyakov/interview-anonymizer/archive/refs/heads/main.zip
anon --version
```

Если оболочка отвечает `anon: command not found`, выполните `uv tool update-shell` и откройте новый терминал.

Ссылка ведет на zip-архив, поэтому не нужны ни git, ни системный Python: на чистом Mac оба заменены заглушками, которые просят поставить инструменты разработчика. Там, где git есть, работает и `uv tool install git+https://github.com/vasilievyakov/interview-anonymizer`.

- uv сам подбирает подходящий Python (от 3.11 до 3.14) и ставит языковые модели вместе с инструментом.
- Около 300 МБ на диске и 0,8 ГБ памяти во время работы.
- Первый запуск занимает 10–25 секунд, пока модели загружаются с диска; дальше около секунды на команду.
- После установки работает без сети.
- Обновить: `uv tool install --reinstall https://github.com/vasilievyakov/interview-anonymizer/archive/refs/heads/main.zip`. Удалить: `uv tool uninstall interview-anonymizer`.
- Ставили до переименования? Найдите старый пакет в `uv tool list` и удалите его: `uv tool uninstall <имя>`.
- Windows на ARM не поддерживается: spaCy не выпускает для нее сборок.

## Как пользоваться

Команды запускаются в папке проекта: там же, в `.anon/`, создается словарь. Другую папку можно указать так: `anon --project ПУТЬ ...`.

```sh
# 0. один раз на проект: публичные названия, о которых исследование, остаются в тексте
anon keep ПульсПлан Ритмо FitBox

# 1. найти все, что похоже на персональные данные, и записать review.csv
anon scan interview-01.md interview-02.md staff.xlsx

# 2. пройти найденное на локальной странице в браузере
anon review --web

# 3. заменить, проверить на утечки, записать interview-01.anon.md и staff.anon.xlsx
anon apply

# 4. отдать файлы *.anon.* модели, сохранить ее ответ, затем
anon restore answer.md        # -> answer.restored.md
```

**Список брендов.** `anon keep` перечисляет бренды, продукты и сервисы, о которых исследование. Они узнаются в любой грамматической форме и в частых искажениях распознавания речи («Фитбокс» вместо «FitBox», «Корзинко» вместо «Корзинка»), в проверке показываются уже решенными и остаются в тексте. Города России с населением больше миллиона и страны остаются всегда; небольшие города, районы, улицы и работодатели скрываются. `anon keep` без аргументов показывает список.

**Проверка.** `anon review --web` открывает страницу на `127.0.0.1` с одноразовым токеном; из сети она ничего не загружает. Найденное разбито на группы: люди, организации, места, номера и контакты. Для каждого значения выбираете «скрыть» или «оставить», название можно одной кнопкой отправить в список брендов, а пропущенное добавить в поле сверху. После «Готово» решения записываются в `review.csv`. С ключом `--no-browser` команда только печатает адрес страницы.

Еще два способа, если они удобнее:

- `anon review` проводит по списку в терминале: Enter скрывает значение, `n` отмечает ложное срабатывание, в конце можно ввести пропущенное. `anon review --add "Санек" --kind PERSON` добавляет одно значение сразу.
- `review.csv` открывается в Excel или Numbers: в колонке `keep` поставьте `no` у ложных срабатываний и добавьте строки для пропущенного.

Решения хранятся в словаре и применяются к каждому следующему файлу проекта. `anon list` печатает список проверки таблицей.

**Замена и возврат.** `anon apply` не записывает файл, если в нем осталось хоть одно известное настоящее значение, и показывает, что осталось и где. `anon restore` возвращает настоящие значения в ответ модели и перечисляет все метки, которые модель исказила (`[ИМЯ_1]-ой`, `PERSON_1` без скобок) или выдумала.

Пароль словаря спрашивается один раз за команду; для скриптов задайте `ANON_PASSWORD`. Сообщения выводятся на языке системы, русском или английском; `ANON_LANG=ru` или `ANON_LANG=en` задает язык явно.

## Пройти руками за 20 минут

Весь цикл на выдуманных данных из репозитория. Запускайте команды в обычном окне терминала, без агента.

**1. Установить и создать учебную папку.** Установка описана выше. Затем:

```sh
mkdir ~/anon-practice && cd ~/anon-practice
R=https://raw.githubusercontent.com/vasilievyakov/interview-anonymizer/main/tests/fixtures
curl -LO $R/live/corpus/01_pulsplan_oleg.md
curl -LO $R/live/corpus/04_grocery_svetlana.md
curl -LO $R/ru/staff.xlsx
```

Два интервью и таблица сотрудников. Откройте интервью и посмотрите, что в нем: имена, телефоны, работодатели, бренды.

**2. Список брендов.**

```sh
anon keep ПульсПлан Ритмо FitBox "Лавка у дома" Корзинка СвежаК "Шеф Классик" Гуру Добрыня "Сырный Двор" "Утро в Заречье"
```

Ответ: «Добавлено в список: 11» и сам список. Эти названия останутся в тексте.

**3. Поиск.**

```sh
anon scan 01_pulsplan_oleg.md 04_grocery_svetlana.md staff.xlsx
```

Первый запуск занимает 10–25 секунд. В конце «Найдено значений: …, файлов: 3», строка о том, сколько совпало со списком брендов, и подсказка про следующий шаг. В папке появился `review.csv`.

**4. Как это видит агент.**

```sh
CLAUDECODE=1 anon list
CLAUDECODE=1 anon review
```

Первая команда печатает только счетчики по типам, без значений. Вторая отказывается работать и просит человека провести проверку в своем окне.

**5. Проверка.**

```sh
anon review --web
```

В браузере откроется локальная страница. Пройдите группы, нажмите «скрыть» или «оставить» у нескольких значений, отправьте одно название кнопкой «в список брендов», добавьте в поле сверху то, что заметили в тексте, но не нашли в списке. Нажмите «Готово». Терминал напишет, сколько значений скрывается, сколько пропускается и сколько добавлено вручную.

**6. Замена.**

```sh
anon apply
```

Словаря еще нет, поэтому `apply` попросит придумать пароль и повторить его. Без пароля метки не вернуть. В конце: «Готово. Контроль утечек пройден». Если написано «ОСТАНОВЛЕНО», в тексте осталось значение, которое вы решили скрыть: добавьте его на странице проверки (шаг 5) и запустите `anon apply` снова. После успешного `apply` файл `review.csv` удаляется: решения уже лежат в зашифрованном словаре.

**7. Посмотреть, что уйдет в модель.**

```sh
open 01_pulsplan_oleg.anon.md      # Linux: xdg-open
open staff.anon.xlsx
```

Вместо имен стоят `[ИМЯ_1]`, `[ИМЯ_2]`, бренды из списка остались. В таблице ФИО и контакты заменены, числа и формулы те же.

**8. Ответ модели.** Отдайте `01_pulsplan_oleg.anon.md` любой модели и сохраните ответ в `answer.md`. Или напишите ответ сами:

```sh
echo 'Итог: [ИМЯ_1] хочет офлайн-режим. С [ИМЯ_2]-ой стоит созвониться.' > answer.md
```

**9. Возврат значений.**

```sh
anon restore answer.md
cat answer.restored.md
```

После пароля в `answer.restored.md` стоят настоящие имена. Про `[ИМЯ_2]-ой` restore напишет отдельно: модель приписала к метке падежное окончание, такое место нужно проверить глазами.

**10. По желанию: скилл и хук.**

```sh
anon install-skill
```

Вставьте напечатанный фрагмент в `~/anon-practice/.claude/settings.json` и запустите Claude Code в этой папке. Попросите прочитать `01_pulsplan_oleg.md`: хук заблокирует. Попросите проанализировать интервью: агент пойдет по шагам скилла и передаст проверку вам.

Убрать за собой: `uv tool uninstall interview-anonymizer` и папка `~/anon-practice`.

## С Claude Code или Codex

Агент видит все, что читает, и все, что печатают команды, и все это уходит в облачную модель. Если агент откроет исходное интервью, «чтобы проверить одну строку», имена покинут ваш компьютер раньше, чем `anon` их заменит. Поэтому агент работает только с файлами `*.anon.*`, а проверку делает человек, вне агента.

**Тихий режим.** Когда `anon` запущен из Claude Code или Codex или его вывод идет не в терминал, ни одна команда не печатает значений из данных. Поиск называет файлы по номеру («файл 2 из 5»), потому что в имени файла может оказаться имя респондента. `anon list` печатает счетчики по типам. Остановленный `apply` выводит номера строк и типы без значений. `restore` сообщает, сколько мест проверить вручную и в каких строках. `anon review` в терминале отказывается работать и просит человека провести проверку в своем окне. Тот, кто сознательно перенаправляет вывод, может вернуть значения переменной `ANON_SHOW_VALUES=1`.

**Скилл и хук для Claude Code.** Вместе с `anon` ставится скилл (`src/anon/claude/SKILL.md`), который ведет агента по шагам: список брендов, поиск, проверка человеком, замена, сама работа и возврат значений, и защитный хук (`src/anon/claude/guard.py`). Установка:

```sh
anon install-skill
```

Команда копирует скилл и хук в `~/.claude/skills/anonymize` и печатает фрагмент для `<проект>/.claude/settings.json`. Хук запускается на Python, который пришел вместе с `anon`, поэтому работает и там, где системного Python нет. Сама команда настроек не меняет; добавьте фрагмент в каждый проект, где лежат данные.

Хук блокирует Read, Grep, Glob, Edit, Write и команды оболочки, которые читают файлы (`cat`, `head`, `grep`, `rg`, `sed`, `awk`, `python`, `cp`, `open` и похожие), если они касаются:

- файлов из последнего поиска в проекте;
- оригинала, рядом с которым лежит обезличенная копия (`interview.md`, когда есть `interview.anon.md`);
- `review.csv`, всего внутри `.anon/`, любых файлов `*.restored.*` и папок, где они лежат.

Еще он блокирует любую команду, которая задает `ANON_SHOW_VALUES`. В сообщении о блокировке путь не приводится: в имени файла может быть имя.

Известные ограничения:

- Хук берет состояние поиска из рабочей папки агента. Файлы проекта, указанного через `--project` в другом месте, защищены только после `anon apply`, по правилу обезличенной копии.
- Локальную страницу проверки хук не перехватывает. Если агент откроет ее адрес, он увидит значения; запрещает это только скилл.
- Хук страхует от честных ошибок. Он покрывает перечисленные выше инструменты и не служит песочницей против агента, который решил его обойти.

**Codex.** Тихий режим в Codex работает так же. Хук есть только для Claude Code. `SKILL.md` написан в общем формате скиллов; чтобы пользоваться им в Codex, выполните `CLAUDE_SKILLS_DIR=<папка, откуда Codex читает скиллы> anon install-skill`.

## Как он находит персональные данные

Три независимых слоя. Значение попадает в список, если его нашел хотя бы один.

| Слой | Что находит | Языки |
|---|---|---|
| Правила | телефоны, почту, СНИЛС, ИНН, паспорта, банковские карты, SSN, британский номер National Insurance. Контрольные суммы проверяются, поэтому суммы, даты и тайм-коды не попадают в список | ru, en |
| [Natasha](https://github.com/natasha/natasha) | имена, организации, места; приводит русские имена в любом падеже к одной форме | ru |
| [spaCy](https://spacy.io) | имена, организации, места, как второе мнение | ru, en |

Поверх них работают фильтры шума расшифровок: метки спикеров и тайм-коды, слова-паразиты, заглавная буква в начале каждой фразы, роли вроде «Интервьюер», общие сокращения (HR, ИП, МФЦ). Затем общий список проверяет человек. Проверка входит в устройство инструмента: автоматический поиск что-то пропускает (см. ниже).

## Почему это безопасно

- **До обезличивания ничего не покидает компьютер.** Поиск и замена выполняются локально. Тест (`tests/test_offline.py`) прогоняет весь путь scan, apply и restore с заблокированной сетью.
- **Контроль утечек останавливает запись.** После замены результат проверяется на все настоящие значения из словаря и все значения, которые вы решили скрыть. Если что-то осталось, файл не записывается.
- **Словарь зашифрован.** `.anon/vault.bin` связывает метки с настоящими значениями. Он зашифрован вашим паролем (scrypt и Fernet); без пароля это бессмысленные байты. Не передавайте его и не коммитьте (он в `.gitignore`).
- **Возврат показывает, в чем не уверен.** Если модель исказила метку или выдумала новую, restore заменяет то, что может, и перечисляет все такие места.

## Как он сделан

Первая версия строилась на чистом синтетическом наборе: выдуманные интервью и таблицы сотрудников на русском и английском, каждое персональное значение размечено вручную (`tests/fixtures/golden.json`). В русском интервью она нашла все 98 размеченных значений.

Потом она встретилась с первыми настоящими исследовательскими интервью и утонула. Список проверки разросся до сотен строк. Метки спикеров склеивались с именами, и «Олег (Speaker A)» становился отдельным человеком. Распознавание речи начинало каждую фразу с заглавной буквы, и слои NER принимали эти слова за имена. Бренды, о которых шло исследование, приходили в десятках искаженных написаний, и каждое занимало свою строку. Один респондент встречался под полным именем, уменьшительным и одной фамилией и получал несколько меток.

Сам инструмент никуда не отправляет данные. Настройка была отдельным решением: владелец интервью разрешил агенту и его субагентам, которые работают на облачной модели, их читать. Значения не попали ни в репозиторий, ни в тесты, ни в историю коммитов; перед каждым пушем история сверялась с эталоном.

Настоящие интервью нельзя положить в репозиторий, поэтому работа началась со способа измерять:

1. **Эталонная разметка.** Субагенты разметили интервью по каждому упоминанию, и каждое упоминание получило уровень: *direct* (частные лица, контакты), *quasi* (работодатели, небольшие города, районы, станции метро), *public* (бренды из исследования, крупные публичные сети, большие города, страны).
2. **Стенд, который печатает только числа.** `scripts/bench.py` прогоняет поиск, проверку и замену как один проект и сообщает строки проверки по классам, долю скрытых упоминаний direct и quasi, ложные метки и людей, разбитых на несколько меток. В его выводе нет значений из данных, поэтому им можно делиться. Ключ `--show` печатает значения и рассчитан на синтетику.
3. **Правки по одной, с замером.** Фильтры шума расшифровок, таблицы в markdown, русские словоформы, сборка частей имени в одного человека, список брендов с поиском искажений, обрезка найденного имени по нужному слову. Каждую правку проверяли на стенде, прежде чем браться за следующую.
4. **Второй синтетический набор.** `tests/fixtures/live` воспроизводит те же трудности на выдуманных людях, работодателях и брендах: склеенные метки спикеров, сырое распознавание речи, искаженные названия брендов, названия продуктов, похожие на имена, один человек в нескольких формах. На нем любой может повторить замер до и после. Подробности в [tests/fixtures/live/README.md](tests/fixtures/live/README.md).

Тогда же появились страница проверки (при сотнях находок люди сдаются именно на проходе в терминале и на таблице), тихий режим, скилл и хук.

## Замеры на синтетических данных

### Чистый набор

| Правила | 12 из 98 | 12 из 98 |

| Русская таблица сотрудников | | 0 | 1 из 125 |
| Английская таблица сотрудников | | 0 | 4 из 166 |

Семь пропусков в английском интервью составляют прозвища и одиночные фамилии («Robbo», «Fairbairn», «Em's»). В обеих таблицах ни одна из 40 формул не изменилась, ни одно число и ни один заголовок тоже. Настройка под живую речь здесь ничего не стоила: в коммите перед ней ложных срабатываний было 9 и 19, утечек 3.

### Набор, похожий на живые интервью, до и после

`scripts/bench.py` на `tests/fixtures/live`: семь файлов, 575 упоминаний direct и 94 quasi, 56 человек. «До» означает первую версию от 2026-10-01, до настройки на живых интервью, с тем же стендом, приспособленным к нему; списка брендов тогда не было. «Сейчас» означает текущую версию. Доля скрытого и метки посчитаны в предположении, что человек скрывает все найденные строки и ничего не добавляет вручную.

| | До | Сейчас | Сейчас, со списком брендов |
|---|---|---|---|
| Строк проверки | 682 | 220 | 220, из них 41 уже решена |
| из них имена и контакты | 152 | 96 | 96 |
| из них работодатели и места | 49 | 42 | 42 |
| из них публичные бренды и большие города | 136 | 66 | 66 |
| из них ничего личного | 345 | 16 | 16 |
| Скрыто имен и контактов | 98,1% | 98,4% | 98,4% |
| Скрыто работодателей и мест | 87,2% | 85,1% | 85,1% |
| Ложных меток (ничего личного) | 898 из 2075, 43,3% | 32 из 1173, 2,7% | 32 из 780, 4,1% |
| Меток на публичных названиях | 536, 25,8% | 494, 42,1% | 101, 12,9% |
| Людей под несколькими метками | 39 из 56 | 20 из 56 | 20 из 56 |

Имена находятся так же, как раньше. Изменилась работа, которая остается человеку: строк для чтения втрое меньше, мусор сократился с половины списка до 7%, те же люди разбиты на меньшее число меток. Работодатели и места скрываются чуть хуже, 85,1% против 87,2%: это цена более строгого отсева мусора в расшифровках без пунктуации, и именно такие пропуски закрывает проверка. Список брендов убирает из результата большую часть публичных названий, и модель по-прежнему видит бренды, о которых ее спрашивают. Доля ложных меток со списком брендов растет только из-за того, что меток всего становится меньше.

Эти числа получены на синтетическом тексте. Живая речь грязнее, поэтому на ваших данных ждите больше пропусков и больше мусора. Значения, оставшиеся в тексте, и есть задача проверки: человек добавляет их на странице, и контроль утечек задерживает их во всех следующих файлах.

## Чего он не ловит

- **Косвенные признаки.** «Единственный бухгалтер нашего тверского филиала» не называет имени, но указывает на человека. Такое ловит только проверка.
- **Распознавание речи строчными буквами.** Оба слоя NER опираются на заглавные буквы. В расшифровке целиком строчными большинство имен пропускается. Работодатель, чье название состоит из обычных слов и записано строчными («работаю в вектор сервис»), остается в тексте: строчное словарное слово считается речью, даже если то же название в другом месте найдено с заглавной.
- **Редкие уменьшительные и незнакомые имена.** Формы вроде «Ванюша», сокращения вроде «Soph» и неанглийские имена в английском интервью часто пропускаются.
- **Мелкие места.** Часть районов, улиц и станций метро пропускается, особенно в косвенных падежах или когда название похоже на прилагательное или на название продукта.
- **Коды интервью, намеренно.** Коды вроде `Инт.12_Hs5nJd` остаются в тексте, чтобы модель могла сослаться на респондента. Это псевдонимы; тот, у кого есть реестр исследования, свяжет их с людьми. Если реестр чувствителен, добавьте коды при проверке.
- **Телефоны без кода страны** («912 345-67-89») и необычные форматы номеров.
- **Редкие числа.** Самая высокая зарплата в небольшой команде может указать на человека и без имени. Числа намеренно остаются как есть.
- **Грамматика модели.** Метки не склоняются. Restore пишет имена в именительном падеже, поэтому «с [ИМЯ_1]» вернется как «с Мария Ковалева». Restore перечисляет места, где модель приписала к метке падежное окончание.
